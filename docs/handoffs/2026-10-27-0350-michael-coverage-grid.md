## Decisions and why
- **The script is `coverage.mjs`, not the `coverage.ts` the prompt named.** Your Mac runs Node 20, which can't run TypeScript, and the TypeScript modules import JSON the Vite way (no import attributes), so plain Node can't load them on any version. Vite's module runner loads them exactly as the tests do, and Vite is already a dev dependency, so no runner was added. The grid logic is TypeScript in `src/content/coverage.ts`, type-checked by `tsc -b` and tested; the script is twenty lines of glue.
- **Only an item's primary skill fills a cell.** Touches are what an item exercises on the way, not content for that skill's role; counting them would hide the inverse-operations gap above.
- **The generator counts as practice, nothing else,** as the prompt said. It isn't an angle, so it doesn't rescue a skill from the one-angle list.
- **Names and ids both appear in the table** (name in bold, id in code), because people read names and the catalog uses ids.
- **Footnotes start at more than two ids** per cell, so today's two four-item repair cells read as counts and the rest stay inline.
- **`content/coverage.ts` imports `DEMO_NODES` and `LEVELS` from `mock/generate`.** The generators are mock code, and the grid has to know which nodes have one; the import doesn't cycle (generate imports nothing from the catalog). When the generators move to Python, this input comes from the server's list instead.
